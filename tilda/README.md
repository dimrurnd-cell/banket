# Перенос в Tilda

Сгенерировано `python3 _src/build_tilda.py`. Каждая страница — **один** блок
«HTML-код», а не набор блоков: вставлять 27 раз, а не 142.

## Что нужно сделать один раз

### 1. Пересобрать после правок фотографий

Если фотографии в `assets/img/photo/` не менялись, этот шаг пропускается —
всё уже собрано. Если менялись:

```
pip install pillow
python3 _src/optimize_images.py
python3 _src/build.py
ASSET_BASE=https://cdn.jsdelivr.net/gh/dimrurnd-cell/banket@5778eb0f261dffffd1bdfc424bfe914a1fd4f01b/assets/ python3 _src/build_tilda.py
```

Скрипт раскладывает каждый кадр по ширинам 400 / 800 / 1280 px в AVIF и WebP
плюс один JPEG для старых браузеров (`assets/img/opt/`) и пишет манифест
`_src/images.json`. Дальше сборка подставляет `<picture>` с `srcset` —
браузер берёт версию под свой экран.

### 2. Откуда берутся файлы

Tilda не хранит произвольные файлы, поэтому 700 с лишним картинок, стили и
скрипт лежат в вашем публичном репозитории на GitHub и раздаются через
**jsDelivr** — бесплатный CDN, который умеет отдавать файлы прямо из
репозитория. Заливать ничего не нужно: всё уже там.

Адрес зашит в блоки и привязан к конкретному коммиту, а не к ветке. Это
важно: коммит неизменяем, поэтому jsDelivr кэширует файлы навсегда и
отдаёт их мгновенно, а новые правки в репозитории не могут сломать уже
работающий сайт.

Вместо длинного номера коммита можно поставить метку — так короче и
понятнее. Из среды сборки метки не пушатся (доступ только к рабочей
ветке), поэтому это делается вручную, один раз:

```
git tag -a assets-v1 -m "Файлы сайта" && git push origin assets-v1
ASSET_BASE=https://cdn.jsdelivr.net/gh/dimrurnd-cell/banket@assets-v1/assets/ python3 _src/build_tilda.py
```

**Сначала проверьте, что CDN открывается у вас.** Из среды, где собирался
сайт, cdn.jsdelivr.net заблокирован, и я не смог это проверить за вас.
Откройте в браузере:

```
https://cdn.jsdelivr.net/gh/dimrurnd-cell/banket@5778eb0f261dffffd1bdfc424bfe914a1fd4f01b/assets/img/photo/gallery-01.webp
```

Если картинка открылась — всё в порядке, вставляйте блоки. Если нет —
не вставляйте, а пересоберите на другой адрес (см. ниже): иначе сайт
останется без фотографий.

#### Стили и скрипт лучше держать не там же

Сейчас `site.css` и `site.js` тоже едут с jsDelivr. Это работает, но цена
отказа у файлов разная: без фотографий страница просто беднее, без стилей
она рассыпается в неформатированный текст.

Самый простой способ убрать этот риск — вставить css прямо в Tilda
(`Пользовательские CSS-стили`, см. раздел 4). Если хочется оставить оба
файла ссылками, положите их в файловый менеджер Tilda — от неё сайт
зависит в любом случае, новой точки отказа не появится:

```
CODE_BASE=https://static.tildacdn.com/ВАШ-ПУТЬ/ ASSET_BASE=https://cdn.jsdelivr.net/gh/dimrurnd-cell/banket@5778eb0f261dffffd1bdfc424bfe914a1fd4f01b/assets/ python3 _src/build_tilda.py
```

Сборщик подставит `CODE_BASE` только под `css/` и `js/`, картинки
останутся на прежнем адресе.

#### Если фотографии меняются

Адрес неизменяем, поэтому под новые файлы нужен новый адрес — коммит
или метка:

```
git commit -am "Новые фотографии" && git push
ASSET_BASE=https://cdn.jsdelivr.net/gh/dimrurnd-cell/banket@$(git rev-parse HEAD)/assets/ python3 _src/build_tilda.py
```

Затем заново вставить изменившиеся блоки. Старые страницы продолжат
работать со старым адресом, пока вы их не тронете, — это защита от
случая «поправил одно фото, а сайт лёг весь».

#### Запасной вариант

Если jsDelivr подведёт, любая другая площадка подключается одной командой —
залить туда папку `assets/` и пересобрать:

```
ASSET_BASE=https://static.banket-na5.ru/assets/ python3 _src/build_tilda.py
```

Свой поддомен на объектном хранилище (Yandex Cloud, Selectel) — самый
устойчивый вариант: в адресах стоит ваш домен, провайдера можно поменять,
не трогая ни одной страницы.

### 3. Фотографии галереи

Страница «Галерея» показывает `assets/img/photo/gallery-01.webp` …
`gallery-27.webp`. Порядок на странице — по номеру.

Чипы фильтров («Залы», «Стол и кухня», «Свадьбы», «Корпоративы»,
«Новый год», «Фуршеты») и подписи к кадрам заданы в `_src/data.py`,
в `GALLERY_GROUPS` и `GALLERY_ALT`. Кадр можно отнести сразу к нескольким
разделам — например, новогодний корпоратив стоит и в «Корпоративах»,
и в «Новом годе». Если убрать всю разметку из `GALLERY_GROUPS`, чипы
исчезнут и галерея станет одной лентой.

### 4. Настройки сайта → Ещё

Одно поле, одна вставка:

- **HTML-код для вставки внутрь HEAD** — содержимое `_global/head-code.html`

Там сразу всё: шрифты, стили, скрипт. Поля «HTML-код перед `</body>`» на
многих тарифах нет, и оно не нужно.

Tilda вставляет этот код сразу после `<head>`, то есть собственный css Tilda
(`tilda-grid-3.0`, он задаёт всем элементам `box-sizing: content-box`)
подключится после нашего. Это не мешает: правила совместимости в конце
`site.css` написаны селекторами из трёх элементов (`html body *`) и
выигрывают у `*` независимо от порядка подключения. Проверено: собранная
страница внутри имитации Tilda сравнивалась со статической по вычисленным
стилям — фон, шрифт, отступы, сетка, кнопки, карточки и пропорции кадров
совпадают, горизонтального переполнения на 390 px нет, ошибок в консоли нет.

#### Если не хотите зависеть от CDN даже в стилях

Оформление — единственное, потеря которого рушит страницу целиком
(фотографии всего лишь не покажутся). Его можно вообще убрать с внешнего
адреса: скопируйте содержимое `_global/custom-css.css` в
**Настройки сайта → Ещё → Пользовательские CSS-стили** и удалите строку
`<link rel="stylesheet" ...site.css...>` из кода в HEAD. Файл
самодостаточен — внутри нет ни одной внешней ссылки.

Скрипт (`site.js`) так вставить нельзя, для него поля нет: он остаётся
строкой в HEAD. Но без скрипта страница просто теряет подбор зала,
анимации и лайтбокс — читать и отправлять заявку можно и без него.

### 5. Фон страниц

Настройки сайта → Шрифты и цвета → цвет фона: **#0B181C**. Иначе при загрузке
будет белая вспышка до применения стилей.

### 6. Шапка и подвал

Создайте служебные страницы «Хедер» и «Футер» (Tilda: «Создать страницу» →
тип «Хедер» / «Футер»), в каждой один блок **T123 «HTML-код»**:

- `_global/header-block.html`
- `_global/footer-block.html`

Никаких стандартных блоков меню Tilda добавлять не нужно — они продублируют
нашу навигацию.

## Что делать для каждой страницы

1. Создать страницу, задать адрес и SEO-поля из `<папка>/seo.txt`
2. Добавить один блок **T123 «HTML-код»**
3. Вставить содержимое `<папка>/block.html`
4. В настройках блока выставить **отступы сверху и снизу = 0**
   (иначе Tilda добавит инлайн-padding и разорвёт полноэкранные секции)

## Форма заявки

Форму даёт **штатный блок формы Tilda** — так получатели заявок (CRM, почта,
Telegram) настраиваются средствами Tilda и точно работают.

Поставьте блок формы на служебной странице «Футер» **выше** блока с HTML-кодом
подвала, чтобы форма шла над контактами. Дальше две настройки:

**1. Якорь.** В настройках блока формы → «ID блока для ссылки» → `zayavka`.
Все кнопки «Проверить дату» и «Получить расчёт» по сайту ведут на `#zayavka`;
без этого они будут вести в никуда.

**2. Имена переменных.** В Tilda подпись поля и имя переменной задаются
отдельно: подпись видит посетитель, имя переменной уходит в CRM и на почту.
Подписи оставляйте свои, а имена задайте так:

| Подпись поля | Имя переменной | Зачем именно так |
|--------------|----------------|------------------|
| Выберите число гостей | `guests` | сюда подставляется число со шкалы «Подбор зала» |
| Выберите дату мероприятия | `event_date` | — |
| Формат мероприятия | `event_type` | сюда подставляется формат с кнопок на страницах |
| Телефон | `Phone` | Tilda CRM распознаёт как телефон лида |
| E-mail | `Email` | Tilda CRM распознаёт как почту лида |

`Phone` и `Email` — с большой буквы: это служебные имена, по которым Tilda
раскладывает контакты в карточке заявки и умеет искать дубли.

Подстановка работает и со старыми именами (`Выберите количество гостей`,
`мероприятие`), и с дословными подписями — код проверяет все варианты.

**3. Согласие на обработку персональных данных.** Добавьте в форму чекбокс
согласия со ссылкой на `/policy` — на сайте есть все нужные документы,
а форма собирает персональные данные. В прежней форме это поле называлось
`soglasiye-persdan`.

Поле «Имя» в вашем списке отсутствует. Не обязательно, но менеджеру проще
перезванивать, зная, к кому обращаться: имя переменной `Name`.

Проверено в симуляции: якорь срабатывает и когда Tilda отдаёт его как `id`
блока, и когда как `<a name>`; число гостей и формат мероприятия

## Что перестанет работать в Tilda

- **Редактирование текста через интерфейс Tilda.** Внутри блока «HTML-код»
  визуального редактора нет. Правки текстов делаются в `_src/pages.py`,
  затем пересборка и повторная вставка блока.
- **Форма заявки** продолжит работать: она отправляется на тот же адрес
  `forms.tildacdn.com/procces/` и внутри Tilda подхватит настоящие
  `data-tilda-project-id` и `data-tilda-page-id` из `#allrecords`.
  Ключ формы задан в `_src/data.py` → `SITE["formskey"]`.
- **Баннер cookie** в новой вёрстке не реализован. В Tilda его можно вернуть
  штатным блоком T972 — он не конфликтует с нашими стилями.

## Проверено

Вёрстка прогонялась в симуляции окружения Tilda: собранные блоки внутри
`.t-rec`, настоящий `tilda-grid-3.0.min.css` и стили страницы, подключённые
**после** нашего кода — ровно так, как это делает Tilda со вставкой в HEAD.

Вычисленные стили сравнивались со статической сборкой: `box-sizing`, фон,
шрифт и отступы body, ширина контейнера, сетка блоков, кнопки, карточки,
пропорции кадров — совпали. Расхождения только там, где их и ждали: в
подвале Tilda нет нашей формы, её даёт штатный блок.

Поведение в той же симуляции: подбор зала считает гостей и называет зал,
шапка залипает при прокрутке, лайтбокс из подвала открывается по клику на
кадр в блоке страницы, «вопрос — ответ» раскрывается. На ширине 390 px
горизонтального переполнения нет. Ошибок в консоли нет.

## Обновление после правок

```
python3 _src/build.py                                    # статическая версия
ASSET_BASE=https://ваш-адрес/assets/ python3 _src/build_tilda.py
```

Затем заново залить `assets/` и вставить изменившиеся `block.html`.
