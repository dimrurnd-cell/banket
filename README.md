# banket-na5.ru

Статический сайт банкетного комплекса «Банкет-Холл» (ВЦ «ДонЭкспоцентр», Ростов-на-Дону).

Страницы собираются генератором из `_src/`, чтобы 24 страницы делили одну шапку,
подвал, форму заявки и один набор стилей. Имена файлов (`page*.html`) сохранены —
`htaccess` и `sitemap.xml` продолжают работать без изменений.

## Сборка

```
python3 _src/build.py     # пересобирает все page*.html и 404.html в корне
```

Зависимостей нет, нужен только Python 3.

## Что где лежит

```
_src/build.py        генератор: шапка, подвал, форма, рендер секций
_src/data.py         бренд, контакты, залы, форматы, фотографии, навигация
_src/pages.py        структура и тексты каждой страницы
_src/legal/          тексты юридических документов (html-фрагменты)
assets/css/site.css  дизайн-система (Jost + JetBrains Mono, палитра петроль/пергамент/латунь)
assets/js/site.js    подбор зала, анимации, галерея, форма
assets/img/          локальные изображения (в т.ч. LCP-фото главной)
page*.html, 404.html собранные страницы — это то, что заливается на сервер
```

Фотографии залов и мероприятий отдаются с `www.donexpocentre.ru` — те же адреса,
что использовались раньше. Фото первого экрана главной лежит локально
(`assets/img/hero-banquet-*.jpg`) и предзагружается: это самая тяжёлая картинка
на пути к первому рендеру.

## Версия для Tilda

Если сайт должен жить внутри Tilda, а не отдельным статическим экспортом:

```
ASSET_BASE=https://ваш-адрес/assets/ python3 _src/build_tilda.py
```

Соберёт папку `tilda/`: по одному HTML-фрагменту на страницу для блока
«HTML-код», отдельно шапку, подвал и код для настроек сайта. Пошаговая
инструкция — в `tilda/README.md`.

## Публикация

1. Скопировать на сервер по FTP: `page*.html`, `404.html`, `assets/`,
   `htaccess`, `robots.txt`, `sitemap.xml`.
2. Переименовать `htaccess` в `.htaccess`.

Каталог `_src/` на сервер загружать не нужно.

## Форма заявки

В **статической** сборке форма встроена в страницу: отправляется на
`https://forms.tildacdn.com/procces/` с теми же именами полей, что были
у формы исходного сайта. Ключ проекта и ID получателя — в `_src/data.py`
(`SITE["formskey"]`, `SITE["formservice"]`).

В сборке **для Tilda** своей формы нет: её даёт штатный блок формы Tilda,
который сам прописывает получателей заявок. Как его подключить и как назвать
поля, чтобы работала подстановка числа гостей и формата, — в `tilda/README.md`.

Переключается флагом: `render_chrome(include_form=False)` в `_src/build_tilda.py`.

## Публикация

1. Скопировать на сервер по FTP: `page*.html`, `404.html`, `assets/`,
   `htaccess`, `robots.txt`, `sitemap.xml`.
2. Переименовать `htaccess` в `.htaccess`.

Каталог `_src/` на сервер загружать не нужно.

## Форма заявки

Форма живёт в подвале и поэтому есть на каждой странице. Кнопки
«Проверить дату» по всему сайту ведут на якорь `#zayavka` внутри неё.
В сборке для Tilda она входит в блок футера — вставлять её в страницы
не нужно.

Отправляется на тот же адрес, что и раньше —
`https://forms.tildacdn.com/procces/` — с теми же именами и значениями полей,
что были в форме исходного сайта. Заявки приходят туда же, куда приходили.

Две настройки в `_src/data.py` определяют, куда попадёт заявка:

| Ключ | Что это | Где смотреть в Tilda |
|------|---------|----------------------|
| `SITE["formskey"]` | Ключ проекта. Подтверждает, что форма принадлежит вашему сайту. | Общий для всех форм проекта |
| `SITE["formservice"]` | **ID получателя.** Именно он решает, кому уйдёт заявка: на почту, в Telegram, в CRM. | Настройки сайта → Формы и приём данных |

Без `formservices[]` бэкенд Tilda примет заявку и вернёт «успех», но доставлять
её будет некому — она просто пропадёт. Если в Tilda подключается новый
получатель, его ID нужно подставить в `SITE["formservice"]` и пересобрать.

Отправляемые поля: `Name`, `messenger-type` (`phone` / `telegram` /
`whatsapp` / `max_messenger`), `messenger-id`, `мероприятие`,
`Выберите дату мероприятия` (в формате ДД-ММ-ГГГГ), `Выберите количество
гостей`, `Email`, `Комментарий`, `soglasiye-persdan`.

## Маркетинговые скиллы

В репозитории подключён набор маркетинговых скиллов
[coreyhaines31/marketingskills](https://github.com/coreyhaines31/marketingskills)
(50 скиллов: копирайтинг, CRO, SEO, реклама, email, аналитика и т.д.).

Подключение объявлено в `.claude/settings.json` — Claude Code сам подтягивает
плагин из GitHub, вендорить в репозиторий ничего не нужно. У любого, кто
склонирует репозиторий, скиллы появятся автоматически.

`.agents/product-marketing.md` — общий контекст о продукте, который каждый из
этих скиллов читает перед работой: позиционирование, аудитория, возражения,
доказательства, tone of voice. Пункты, помеченные `[уточнить]`, ещё не
подтверждены — их нельзя использовать в текстах как факты.
Обновлять контекст: `/product-marketing`.
