# Полный сайт — второй вариант

27 страниц в едином дизайне: 19 основных, 7 правовых документов и 404. Главная, каталог залов, три зала, каталог событий, свадьбы, корпоративы, новогодние корпоративы, дни рождения, фуршеты, кофе-брейки, выпускные, детские праздники, поминальные обеды, кейтеринг, аренда оборудования, галерея и контакты связаны общей навигацией.

Используется присланный логотип. В шапке он отображается чёрным через CSS, в подвале — белым. Исходный файл сохранён без изменений.

## Сборка и просмотр

Нужен Python 3.10+. Дополнительные пакеты для сборки не требуются.

```text
python _src/build_full_v2.py
python _src/verify_full_v2.py
python _src/preview_variant2.py
```

Открыть http://127.0.0.1:8766/variant2.html. Все короткие адреса работают в локальном сервере. Сервер старого варианта на порту 8765 — отдельный предпросмотр.

Для этой версии использовать `build_full_v2.py`. Прежние `build.py` и `build_variant2.py` относятся к предыдущим вариантам и перезапишут их выходные файлы.

## Формы и Tilda CRM

Используется штатная форма из актуального экспорта и её оригинальные библиотеки Tilda, включая проверку полей, маску телефона, календарь и обработку ответа сервера. Самописный транспорт предыдущего варианта не используется: новый form ID не совпадает с `request-form`.

В интерфейсе Tilda проекта **25155506 «Банкет Холл»** проверены активные получатели и подключение ко всем формам. В содержимом общей формы **3493827001** подтверждены четыре выбранных сервиса:

- ads@donexpocentre.ru;
- koroleva@donexpocentre.ru;
- congress2@donexpocentre.ru;
- Tilda CRM → **Банкет Холл Заявки**.

Идентификаторы получателей сохранены в `_src/form-services-v2.json`; все четыре включены в каждую форму нового проекта. Это публичные идентификаторы приёмщиков, используемые штатной формой, а не пароли или API-ключи. Поля `guests`, `event_date`, `event_type`, `Name`, `Email`, `Phone` сохранены для совместимости с действующими заявками. Формат автоматически заполнен на соответствующей странице; число гостей переносится из подбора.

**Статус:** настройки сервисов в Tilda сохранены. Чтобы изменения попали в уже опубликованный сайт, требуется переопубликовать страницы. Новая версия дизайна на рабочий домен не переносилась. Реальные тестовые заявки не отправлялись, доставка письма в каждый ящик не подтверждена. Локальный сервер блокирует отправку и явно сообщает об этом.

Tilda принимает формы только с разрешённых доменов проекта и при действующей подписке. Проверенные домены: `banket-na5.ru`, его поддомены, `banket-na5.tilda.ws`, `project25155506.tilda.ws`. Подробности: [формы](https://help.tilda.cc/forms), [email](https://help.tilda.cc/forms/email), [Tilda CRM](https://help.tilda.cc/tilda-crm).

## Размещение

**На отдельном хостинге:** разместить сгенерированные `page*.html`, `404.html`, папку `assets`, `.htaccess`, `robots.txt` и `sitemap.xml` в корне домена. Правила Apache связывают короткие адреса с файлами. На другом сервере использовать карту `_src/routes-v2.json`. Формы сохраняют привязку к исходному проекту Tilda.

**На Tilda:** папка `tilda/full-v2` содержит блок и SEO-поля для каждой страницы. Блок включает собственные шапку, подвал и форму; его следует размещать на отдельной чистой странице без прежних общих шапки/подвала и старого контентного блока. Стили и скрипты ссылаются на ветку `codex/complete-site-v2` через jsDelivr. Для выпуска рекомендуется закрепить CDN на проверенном commit SHA через переменную `ASSET_BASE` при сборке. Ветка должна быть доступна на GitHub до проверки блоков. Нельзя вставлять два полных блока на одну страницу: повторятся ID формы.

Подготовка файлов не означает публикацию в редакторе Tilda. Перед заменой рабочего сайта сначала проверить отдельную тестовую страницу, затем переносить согласованную версию и переопубликовать проект.
